# 講者與學員操作指引

## 分享主線

**問題發覺 → 條件式實作 → 品質驗證 → 人的工作改變。**
三案各自回答：修正能否重用、動作何時允許、交付能否用完。所有互動都是教學實作，歷史研究數字另列。

## 現場操作建議（15–20分鐘活動）

### 第一站：DrawIQ（約5分鐘）

先選「上限與下限不同」，維持「歷史缺口示意」，按檢查。看到建議仍然出現後，先問聽眾是否應採納，再模擬採納：已有內容但仍待審。改用補強規則，建議被攔截。再比較「衝突」「待決策」「來源撤回」與「證據框調整」。

預期產出：規則是否啟用、條件是否相符、未檢查風險與採納狀態。

討論：看過去的核准紀錄能省下什麼？看更多依據又增加哪些覆核工作？如何以最終關鍵欄位錯誤與覆核時間驗證？

### 第二站：醫療器械配對（約6分鐘）

執行「及早闖入後離開」，觀察有閘門減速等待後恢復，無閘門出現示例碰撞。切換「過晚才出現的障礙」，觀察即使有閘門仍會失敗；切換「持續佔區」，觀察中止。拉動時間軸查看時刻狀態。

再執行24組固定種子情境。說明同一種子保留同一套考題，48次執行不是48個真人受試者。匯出CSV後可比較兩邊都成功、只有一邊成功、兩邊都未完成。

討論：失敗提早結束會不會讓平均時間變短？為何停止不等於任務成功？歷史92.0%來自原物理模擬，不能拿新玩具模型替代。

### 第三站：教學平台部署（約5分鐘）

在「新機／乾淨安裝」按「只跑舊檢查」：9/9通過，但範圍只有9/28。改驗全部，點教案21，看只存在開發機的結構缺失。勾選各項修正後逐步驗收；或按「完整發布修正」。

修正通過後注入損毀檔案，再取消媒體完整性核對：可看到28個宣告可播，實際只有27個可用。重新核對只會攔截；按完整發布修正才恢復示例檔案。

討論：驗收清單應由使用者可選流程產生，還是只由已產製內容產生？清楚的錯誤原因如何降低重試與求助？

## 帶走成果

在「學習紀錄」匯出活動JSON，保留每站最後結果與操作事件；第二站另可匯出24列CSV。可列印成紙本或由瀏覽器另存PDF。每人自行保存，沒有雲端集中收集。

操作後0–10自評為選填且預設不記錄；需按儲存才進入JSON。它是自製課堂回饋，不是正式問卷、NASA-TLX或能力評量。

## 研究使用界線

這些課堂活動不自動構成可發表的人因研究。正式蒐集需事先處理同意、資料管理、任務匹配、順序平衡與獨立分析單位。不能將連續影格、重複點擊或多配置執行直接當成獨立人數，也不能只看少按按鈕就宣稱負荷降低。

## 離線與備援

公開連線不穩時，用預先保存的單一HTML；受限環境改用Python標準庫啟動本機HTTP。原始碼ZIP包含建置與測試，不需要外部模型或GPU。首次演講前請在實際投影設備與至少一台現場手機開啟三站，並測一次匯出。
